# Visual & Layout Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle all 7 screens in a clean-fintech look with a phone bottom tab bar (+ More page) and a desktop sidebar, without changing features, data, or accessible names.

**Architecture:** One hand-written design system in `src/styles.css` (tokens on `:root` + component classes), three small presentational components (`Icon`, `PageHeader`, `Money`), a `cx` class helper, a new `/more` route, then screen-by-screen JSX restructuring that only adds wrappers/classes. Tests find elements by role/label/text, so they keep working; the one test that asserts exact concatenated text (Upcoming payments) is updated to the same intent.

**Tech Stack:** Vite 8, React 19, TypeScript strict, react-router-dom 7 (HashRouter), Vitest 5 + Testing Library + jsdom, Playwright (chromium + webkit).

**Spec:** `docs/superpowers/specs/2026-09-30-redesign-design.md`

## Global Constraints

- No new dependencies (runtime or dev). No paid fonts/services. System font stack only.
- Always light: keep `color-scheme: light` on `:root` and the `<meta name="color-scheme" content="light">`.
- Do not reword any visible text, button name, label, heading, `aria-label`, `role`, or message — except: the 🥇 emoji becomes a "Best" chip; the phone tab shows "Home" while the link's accessible name stays "Dashboard"; new "More" link/page; the "Reading…" step gains a spinner.
- Touch targets ≥ 44px tall on phones (≤ 700px); form inputs use `font-size: 16px` (prevents iOS zoom-on-focus).
- Phone breakpoint: `max-width: 700px`.
- Wordmark text: `Cashback Tracker` (never "Finory" — that is another company's brand).
- Never commit anything from `statements-samples/`, PDF passwords, or card numbers.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Command-line deletes are blocked; if a file must be deleted, tell the user the full path.

## Review Focus

1. **Tests that match exact text in one node** (`getByText('RM5.00')`, `getByText('Card B')`, `getByText(/RM1,234.50/)`, `getByText('RM61.70')`): new wrappers must keep each such value as the *only* text of its element and must not duplicate it elsewhere on the page (e.g. don't show an amount twice). Every task runs its feature's tests.
2. **Long card names / big amounts on a 375px phone**: header rows (`.card-head`, `.rows > li`) must wrap, not overflow sideways. CSS uses `flex-wrap`, `min-width: 0`, and `overflow-wrap: anywhere`; verified in Task 9 screenshots at 390px.
3. **Bottom tab bar covering content / the iPhone home indicator**: `.main` phone bottom padding includes the bar height + `env(safe-area-inset-bottom)`; `viewport-fit=cover` added. Verified in Task 9 WebKit screenshot of a long page scrolled to the bottom.
4. **More tab highlighted on Cards/Reports/Settings** (user is "inside" More): Layout test in Task 3 pins `active` class on the More link at `/cards`.
5. **iOS zoom when tapping an input** (inputs < 16px make Safari zoom the page): Task 1 sets inputs to 16px; verified in Task 9 by checking computed font-size in WebKit.

```ts
/** Joins the truthy class names: cx('a', cond && 'b') → 'a b' or 'a'. */
export function cx(...parts: Array<string | false | null | undefined>): string {
  return parts.filter(Boolean).join(' ');
}
```
